# VBA и автоматизация

## Цели и требования

Расчеты предыдущих занятий выполнялись формулами и запросами. Здесь рассматривается задача иного типа: повторяемая последовательность действий над таблицей. Пример – классификация строк отчета план-факт по двум порогам с записью статуса, форматированием и контрольными количествами. Вручную такая операция выполняется за несколько минут, но при каждом обновлении данных повторяется заново и допускает ошибки.

После занятия нужно уметь:

- сохранять книгу с макросами и запускать код безопасно;
- обращаться к листам и диапазонам без опоры на активный лист и выделение;
- определять границу данных динамически;
- записывать условия с учетом приоритета правил и граничных значений;
- применять цикл к диапазону и выносить настройки в параметры процедуры.

> [!WARNING]
> Макросы запускаются только в файлах известного происхождения. Код VBA имеет доступ к файлам и настройкам компьютера, поэтому книгу из неизвестного источника нельзя открывать с включенными макросами. Отмена действий макроса клавишами Ctrl+Z невозможна: практика выполняется в рабочей копии.

> [!NOTE]
> Требуется Windows и Excel 2021 либо Microsoft 365. Редактор кода открывается клавишами Alt+F11. Синтаксис VBA не локализуется: ключевые слова пишутся по-английски.

Данные: лист «Отчет» с заголовком в строке 4 и 48 строками данных (до строки 52). Идентификатор в столбце A, плановые и фактические выручка и затраты в столбцах E:H. Столбцы I:K заполняет процедура, блок N5:N9 содержит контрольные количества. Пороги находятся на листе «Параметры».

## 1. Макросы, форматы и среда

Код VBA хранится внутри книги. Формат xlsx его не сохраняет, поэтому рабочая копия записывается как «Книга Excel с поддержкой макросов» (xlsm). Исходный xlsx остается чистой копией.

Процедура без возвращаемого значения объявляется ключевым словом `Sub`:

```excel
Option Explicit

Sub HelloMacro()
    MsgBox "Макрос выполнен"
End Sub
```

`Option Explicit` в первой строке модуля требует объявлять каждую переменную. Опечатка в имени тогда превращается в ошибку компиляции, а не в новую пустую переменную с неверным результатом.

Переменные объявляются оператором `Dim` с указанием типа:

- `Worksheet`, `Range` – объекты Excel; присваиваются ключевым словом `Set`;
- `Long` – целые числа, в том числе номера строк;
- `Double` – числа с дробной частью: суммы, проценты, пороги;
- `String` – текст.

```excel
Dim ws As Worksheet
Dim lastRow As Long
Set ws = ThisWorkbook.Worksheets("Отчет")
lastRow = 52
```

Для отладки процедура выполняется по шагам клавишей F8, результат промежуточных значений выводится командой `Debug.Print` в окно Immediate (Ctrl+G).

## 2. Макрорекордер и его ограничения

Макрорекордер записывает действия пользователя в код. Он показывает соответствие действий объектам и свойствам: полужирный шрифт соответствует `Font.Bold`, выравнивание – `HorizontalAlignment`.

Запись форматирования заголовка `A4:K4` дает код вида:

```excel
Sub Macro1()
    Range("A4:K4").Select
    Selection.Font.Bold = True
    With Selection
        .HorizontalAlignment = xlCenter
    End With
End Sub
```

В записанном коде две зависимости, которые делают процедуру ненадежной:

- адрес `A4:K4` записан явно и не учитывает изменение таблицы;
- действие выполняется над выделением (`Selection`) на активном листе: при запуске на другом листе будет отформатирован не тот диапазон.

Рекордер используется как справочник по именам свойств. Рабочий код переписывается: выделение убирается, лист указывается явно.

```excel
Sub FormatHeader()
    Dim ws As Worksheet
    Set ws = ThisWorkbook.Worksheets("Отчет")

    With ws.Range("A4:K4")
        .Font.Bold = True
        .HorizontalAlignment = xlCenter
    End With
End Sub
```

Конструкция `With...End With` задает объект один раз для нескольких обращений. Комментарий в VBA начинается с апострофа.

```quiz

```

## 3. Объектная модель

Excel организует данные как иерархию: приложение, книга, лист, диапазон, ячейка. Обращение к ячейке записывается цепочкой:

```excel
ThisWorkbook.Worksheets("Отчет").Range("A5").Value
```

Такая ссылка называется квалифицированной: каждый уровень указан явно. Она работает одинаково при любом активном листе.

### ThisWorkbook и ActiveWorkbook

`ThisWorkbook` – книга, в которой находится выполняемый код. `ActiveWorkbook` – книга, активная у пользователя в данный момент. Если одновременно открыто несколько файлов, эти объекты различаются. Для обращения к собственным данным и настройкам используется `ThisWorkbook`.

### Range и Cells

`Range("A5")` задает ячейку или диапазон по адресу в виде текста. `Cells(строка, столбец)` задает ячейку по номерам, что удобно в цикле. Столбец допускается указывать буквой:

```excel
ws.Cells(5, "F").Value
```

Свойство `.Value` читает или записывает значение ячейки.


## 4. Динамическая граница данных

Фиксированный адрес `A4:K52` перестает работать при добавлении строк. Граница определяется программой: поиском последней заполненной ячейки от конца листа вверх.

```excel
Dim lastRow As Long
lastRow = ws.Cells(ws.Rows.Count, "A").End(xlUp).Row
```

`ws.Rows.Count` возвращает число строк листа, `Cells(…, "A")` указывает последнюю ячейку столбца A, `End(xlUp)` соответствует клавишам Ctrl+↑, `.Row` возвращает номер строки. Диапазон строится склейкой текста и числа:

```excel
Set rngData = ws.Range("A4:K" & lastRow)
```

При `lastRow` = 52 получается `A4:K52`, при 58 – `A4:K58`; код не меняется.

### Опорный столбец

Столбец для определения границы должен быть заполнен для каждой записи до запуска процедуры. Столбец K со статусом не подходит: его заполняет сама процедура, при первом запуске он пуст. Идентификатор в столбце A обязателен для каждой строки.

### Другие способы

- `ws.Range("A4").CurrentRegion` – непрерывная область; пустая строка или столбец прерывают ее.
- `ws.ListObjects("имя").DataBodyRange` – тело структурированной таблицы.

Выбор определяется гарантированной структурой источника. Если под заголовком нет данных, `End(xlUp)` вернет строку заголовка; обработка такого входа рассматривается на занятии 7.2.

```quiz

explanation: Опорный столбец должен быть заполнен до запуска и обязателен для каждой записи. Результат работы процедуры на роль опоры не подходит.
```

## 5. Условия If...ElseIf...Else

Для каждой строки рассчитываются два относительных отклонения:

```excel
revenueDelta = (factRevenue - planRevenue) / planRevenue
costDelta = (factCost - planCost) / planCost
```

Направления ухудшения противоположны: для выручки неблагоприятно отрицательное отклонение, для затрат – положительное. Строка считается критичной, если выручка ниже плана не менее чем на порог либо затраты выше плана не менее чем на порог.

```excel
If revenueDelta <= -revenueThreshold Or costDelta >= costThreshold Then
    statusText = "Критично"
ElseIf revenueDelta < 0 Or costDelta > 0 Then
    statusText = "Отклонение"
Else
    statusText = "В норме"
End If
```

### Порядок ветвей

Ветви проверяются сверху вниз, выполняется первая истинная. Строка со снижением выручки на 12 % удовлетворяет и условию `revenueDelta < 0`. Если менее строгое правило поставить первым, строка получит статус «Отклонение», а до критического критерия проверка не дойдет. Правила располагаются по приоритету: от самого строгого к самому мягкому.

### Or и And

`Or` означает, что достаточно одного неблагоприятного признака. `And` потребовал бы провала по обоим показателям одновременно: строка с падением выручки на 14 % при нормальных затратах критичной бы не стала. Выбор оператора – бизнес-правило, а не синтаксис.

### Границы

Отклонение ровно минус 5 % по выручке попадает в «Критично» из-за оператора `<=`; затраты ровно плюс 5 % – из-за `>=`. Ошибка в знаке сравнения меняет результат только на границе.

> [!TIP]
> В учебных данных нет строк с отклонением ровно 5 %, поэтому случайный запуск ошибку знака не обнаружит. Граница проверяется отдельной процедурой с заданными значениями: план 1 000 000 и факт 950 000 должны дать «Критично», факт 960 000 – «Отклонение». Для десятичных долей, не представимых точно, сравнение на границе зависит от округления; проверка на заданных числах выявляет такие случаи.

Перед циклом проверяются не менее четырех случаев: нормальная строка, умеренное отклонение, критическое снижение выручки, критическое превышение затрат. Пример смешанного случая – строка ID 26 (лист, строка 30): выручка ниже плана на 4,95 %, порог не пройден, затраты выше плана на 5,91 %. Статус «Критично» получен только за счет второго условия.

## 6. Циклы For и For Each, Select Case

Алгоритм, проверенный на отдельных строках, применяется ко всем записям от строки 5 до `lastRow`:

```excel
For i = 5 To lastRow
    ' действия для строки i
Next i
```

Переменная `i` принимает значения 5, 6, … `lastRow` включительно. Внутри одной итерации выполняются все действия для текущей строки: чтение плана и факта, расчет двух отклонений, определение статуса, запись трех значений.

```excel
For i = 5 To lastRow
    revenueDelta = (ws.Cells(i, "F").Value - ws.Cells(i, "E").Value) _
                   / ws.Cells(i, "E").Value
    costDelta = (ws.Cells(i, "H").Value - ws.Cells(i, "G").Value) _
                / ws.Cells(i, "G").Value

    If revenueDelta <= -revenueThreshold Or costDelta >= costThreshold Then
        statusText = "Критично"
    ElseIf revenueDelta < 0 Or costDelta > 0 Then
        statusText = "Отклонение"
    Else
        statusText = "В норме"
    End If

    ws.Cells(i, "I").Value = revenueDelta
    ws.Cells(i, "J").Value = costDelta
    ws.Cells(i, "K").Value = statusText
Next i
```

Знак подчеркивания в конце строки продолжает инструкцию на следующей строке. Переменные объявляются до цикла, значения присваиваются на каждой итерации. Если блок `If` оказался после `Next i`, все строки получат статус последней записи.

### For Each и Select Case

Для перебора объектов, например ячеек диапазона, удобнее `For Each`. Конструкция `Select Case` назначает действие по одному из готовых значений:

```excel
For Each cell In ws.Range("K5:K" & lastRow)
    Select Case cell.Value
        Case "Критично"
            cell.Interior.Color = RGB(244, 204, 204)
        Case "Отклонение"
            cell.Interior.Color = RGB(255, 242, 204)
        Case "В норме"
            cell.Interior.Color = RGB(226, 240, 217)
    End Select
Next cell
```

`For` выбирается, когда нужен номер строки, `For Each` – когда нужен перебор объектов. `If` выражает интервалы и составные условия с порогами, `Select Case` – выбор по перечню готовых значений. Цвет является дополнительным сигналом: статус записан текстом.

Столбцы A:H – вход, процедура их не изменяет. Результат записывается в `I:K` и в контрольный блок. Области, которые разрешено изменять, определяются до запуска и служат критерием проверки.

Контрольные количества при порогах 5 %: 48 записей – 9 «Критично», 31 «Отклонение», 8 «В норме»; после добавления шести строк (54 записи) – 9, 34 и 11.

## 7. Параметризованная процедура

Порог 5 % можно записать прямо в условие, но при изменении требования значение придется искать в коде. Настройка и алгоритм разделяются: процедура получает пороги аргументами.

```excel
Sub PrepareReport(ByVal revenueThreshold As Double, _
                  ByVal costThreshold As Double)

    ' общий алгоритм: lastRow, цикл, условия, запись, оформление

End Sub

Sub RunReport()
    PrepareReport _
        ThisWorkbook.Worksheets("Параметры").Range("B5").Value, _
        ThisWorkbook.Worksheets("Параметры").Range("B6").Value
End Sub
```

`RunReport` читает настройки и запускает алгоритм, `PrepareReport` выполняет алгоритм. У каждой процедуры одна зона ответственности. Лист «Параметры» служит конфигурацией, VBA – исполнителем; даже вспомогательное обращение к листу настроек квалифицируется через `ThisWorkbook`.

`ByVal` означает передачу значения: процедура работает с копией и не изменяет исходную ячейку или переменную. Сравнение `ByVal` и `ByRef` выходит за рамки занятия.

Параметризация упрощает проверку: одну процедуру можно запустить с порогами 5 % и 7 % и сравнить контрольные количества. Значение параметра не должно быть пустым: пустая ячейка передается как 0, и правило с этим порогом срабатывает почти для каждой строки.

## 8. Использование ИИ: разбор ошибки и проверка кода

Языковая модель применяется для объяснения сообщения об ошибке и поиска зависимости кода от состояния интерфейса. Контрольные количества она подтвердить не может: они проверяются запуском.

```excel
Ниже приведена моя процедура VBA для Excel и описание задачи:

[ВСТАВЬТЕ КОД ПРОЦЕДУРЫ, ТЕКСТ ОШИБКИ (ЕСЛИ ЕСТЬ), ОПИСАНИЕ СТРУКТУРЫ ЛИСТА И ПРАВИЛ КЛАССИФИКАЦИИ]

1. Найди места, где код зависит от активного листа, активной книги или выделения, и предложи квалифицированные ссылки.
2. Проверь, нет ли жестко заданных номеров строк и столбцов, которые должны определяться динамически.
3. Проверь порядок ветвей условия: не перехватывает ли менее строгое правило строки, предназначенные строгому.
4. Проверь, что вся логика обработки строки находится внутри цикла.
5. Укажи значения, которые являются настройкой и должны передаваться параметрами.
6. Объясни текст ошибки и назови конкретную причину.
7. Не предлагай обработку ошибок через On Error Resume Next.
```

Предложенный код проверяется запуском на учебной копии и сверкой контрольных количеств. Характерный признак ненадежного совета в этой теме – предложение подавить ошибку вместо устранения причины.

## 9. Итоги занятия

1. Код VBA является частью книги и требует формата xlsm; макросы запускаются только в файлах известного происхождения.
2. Макрорекордер показывает имена объектов и свойств, но записывает зависимость от интерфейса, которую нужно убирать.
3. Надежная процедура обращается к объекту по цепочке книга, лист, диапазон; `ThisWorkbook` указывает на книгу с кодом.
4. Граница данных определяется динамически по обязательному опорному столбцу.
5. В каскаде `If...ElseIf` правила расположены по приоритету; знаки сравнения проверяются на граничных значениях.
6. Вся логика обработки строки находится внутри цикла; `For` перебирает номера, `For Each` – объекты.
7. Настройки передаются параметрами, процедуры разделены по зонам ответственности.
