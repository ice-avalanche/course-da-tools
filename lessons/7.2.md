# Автоматизация регулярной отчетности и расчетов

## Цели и требования

Занятие продолжает 7.1. Адресация объектов, динамическая граница, условия, циклы и параметры позволяют автоматизировать расчет на одном листе. Здесь те же конструкции переводятся в устойчивый регламентный процесс. Финансовая логика не усложняется: формула отклонения прежняя. Меняется надежность исполнения: поведение при неверном источнике, применение одного алгоритма к серии объектов, закрытие файлов, выбор инструмента.

После занятия нужно уметь:

- описывать контракт входа и обосновывать отказ от расчета при его нарушении;
- создавать пользовательскую функцию без побочных действий;
- обрабатывать ошибки через единый выход и вести журнал;
- применять одну процедуру к нескольким листам и файлам с явным фильтром области;
- выбирать между формулами, Power Query и VBA.

> [!NOTE]
> Требуется Windows и Excel 2021 либо Microsoft 365. Материалы: книга [lesson-7.2.xlsx](materials/lesson-7.2.xlsx) и архив с четырьмя файлами выгрузок [lesson-7.2-exports.zip](materials/lesson-7.2-exports.zip). Архив распаковывается в локальную папку, книга сохраняется как xlsm, путь к папке записывается в ячейку B8 листа «Параметры».

> [!IMPORTANT]
> Два из четырех файлов выгрузок дефектны намеренно: в `03_March_error.xlsx` отсутствует столбец «Факт затрат, руб.», в `04_April_type.xlsx` одно значение выручки записано текстом. Файлы не исправляются: процедура должна обнаружить дефект, записать причину в журнал и продолжить обработку.

Занятие не является курсом программирования. Новых конструкций немного: `Function`, `On Error GoTo`, `Dir`, `Err.Raise`. Основной результат – архитектура повторяемого процесса.

## 1. От макроса к регулярному процессу

Процесс регулярен, если повторяется на новых данных с одинаковой логикой. Если каждый месяц приходится открывать редактор и менять номер строки, путь или имя листа, процесс не доведен до регламентного состояния.

### Успех выполнения и полнота результата

Тридцать филиалов присылают файлы, один содержит неверный заголовок. Остановка без объяснения оставляет неизвестным, какая часть данных обработана. Пропуск файла без отметки опаснее: процедура завершится без ошибок, и сумма по 29 филиалам будет принята за сумму по тридцати. Поэтому журнал и счетчик обработанных источников являются частью контроля, а не сервисной функцией.

### Контракт входа

Процесс не обязан обрабатывать любой файл. Контракт определяет: где находятся источники, как называется лист, какие заголовки обязательны, какого типа значения. При нарушении контракта корректное поведение – отказ от расчета с записью причины.

### Идемпотентность

Повторный запуск на тех же входах не должен накапливать дубликаты и менять исходные данные. Поэтому выходная область очищается перед записью, а входные данные открываются только для чтения.

Схема, к которой привязан весь материал занятия:

```excel
получить объект → проверить вход → выполнить расчет →
зафиксировать результат → при ошибке сохранить контекст →
в любом случае выполнить cleanup
```

```quiz
question: Процедура обработала 29 файлов из 30, один пропущен без записи, ошибок не возникло. Почему результат считается опасным?
A: VBA не обрабатывает более 25 файлов за запуск
B: Пользователь примет сумму по 29 источникам за полный результат, не имея признака неполноты
C: Пропущенный файл останется открытым
D: Порядок файлов при следующем запуске изменится
correct: B
explanation: Успешное завершение процедуры не означает полноты результата. Процесс, способный пропустить вход без явного признака, превращает неполные данные в внешне корректный отчет.
```

## 2. Пользовательские функции

На 7.1 статус рассчитывался внутри `Sub`. Если та же логика нужна в ячейках листа, создается `Function` – пользовательская функция (UDF). Она похожа на встроенную: интерфейс определяют аргументы и возвращаемое значение, а не последовательность действий.

```excel
Public Function VarianceStatus( _
    ByVal planRevenue As Double, _
    ByVal factRevenue As Double, _
    ByVal planCost As Double, _
    ByVal factCost As Double, _
    ByVal revenueThreshold As Double, _
    ByVal costThreshold As Double) As Variant
```

`Double` подходит для денежных и процентных величин. `ByVal` фиксирует, что функция получает значения и не меняет переменные вызывающего кода. `Variant` нужен, потому что результат бывает двух видов: текст статуса или ошибка Excel.

### Функция без побочных действий

> [!IMPORTANT]
> Во время пересчета листа функция не должна открывать книги, форматировать соседние ячейки, удалять строки, активировать листы, показывать окна. Порядок пересчета определяет Excel, побочные действия делают результат непредсказуемым. Правило: аргументы на вход, результат на выход.

### Зависимости

Функция участвует в графе зависимостей только через переданные аргументы. Если внутри нее прочитать другую ячейку через `Range`, не передав аргументом, значение ячейки изменится, а функция не пересчитается. Поэтому пороги также передаются аргументами, например ссылками на `Параметры!$B$5` и `Параметры!$B$6`. При изменении порога Excel пересчитает функцию сам.

### Контролируемая ошибка

Нулевой план делает относительное отклонение неопределенным. Функция сообщает об этом стандартной ошибкой:

```excel
If planRevenue <= 0 Or planCost <= 0 Then
    VarianceStatus = CVErr(xlErrValue)
    Exit Function
End If
```

Пустая строка скрыла бы проблему: ее нельзя отличить от незаполненной ячейки. Если в аргумент типа `Double` передан текст, Excel возвращает #ЗНАЧ! до вызова кода функции.

### Нужна ли UDF

Если правило прозрачно выражается стандартными функциями или `LET`, VBA требует обоснования: код имеет стоимость – формат xlsm, политика безопасности, сопровождение, необходимость входить в редактор для правки. UDF оправдана при сложной логике, повторяющейся в нескольких местах.

```quiz
question: В UDF добавлена строка, окрашивающая соседнюю ячейку в красный цвет при статусе «Критично». Почему это ошибка проектирования?
A: VBA не позволяет менять цвет из функции
B: Функция обязана возвращать String
C: Функция должна быть чистым вычислением: порядок пересчета определяет Excel, побочные действия делают модель непредсказуемой

correct: C
explanation: Function вычисляет значение, Sub выполняет действия. Смешение слоев делает результат побочных действий зависящим от момента пересчета.
```

## 3. Обработка ошибок и журнал

Ошибки делятся на три группы с разными маршрутами обработки:

- **ошибка кода** (опечатка в имени листа) – исправляется, а не обрабатывается;
- **ошибка среды** (файл отсутствует, путь недоступен) – ожидается при эксплуатации;
- **нарушение контракта данных** (файл открылся, но нужного столбца нет).

Обработчик проектируется для двух последних групп.

> [!WARNING]
> Обработчик не должен скрывать дефекты кода. Если процедура падает из-за опечатки, правильное действие – исправление опечатки.

### Единый выход

```excel
Private Sub ProcessOneSheet(ByVal ws As Worksheet, _
                            ByVal revenueThreshold As Double, _
                            ByVal costThreshold As Double)

    On Error GoTo ErrHandler

    ' основной алгоритм

CleanExit:
    Exit Sub

ErrHandler:
    LogError ws.Name, "ProcessOneSheet", Err.Number, Err.Description
    Resume CleanExit

End Sub
```

`On Error GoTo ErrHandler` передает управление на метку при ошибке, а объект `Err` содержит `Number` и `Description`. Метки пишутся с первой позиции строки. Блок `CleanExit` с `Exit Sub` обязателен: без него нормальное выполнение продолжится ниже, в обработчик, и процедура запишет несуществующую ошибку. `Resume CleanExit` переводит выполнение на безопасное завершение; простой `Resume` повторяет сбойную инструкцию и может зациклиться.

Обработчик короткий: фиксирует проблему, восстанавливает минимальное состояние и выходит.

### Журнал

`LogError` записывает в лист «Журнал» пять полей: время, источник, этап, код, описание. Этап необходим: одинаковый `Err.Description` без указания этапа не позволяет определить место сбоя. Пароли, значения защищенных источников и выгрузки данных в журнал не записываются.

### On Error Resume Next

Оператор допустим только на одной ожидаемой операции с немедленным отключением и явной проверкой результата:

```excel
On Error Resume Next
Set ws = wb.Worksheets("Данные")
On Error GoTo 0

If ws Is Nothing Then
    Err.Raise vbObjectError + 1002, , "Лист Данные отсутствует"
End If
```

Применение на всю процедуру означает, что неверный диапазон, отсутствующая книга или ошибка типа будут проигнорированы. Результат окажется неполным при внешнем успехе – самый опасный класс дефектов в отчетности.

```quiz
question: Перед меткой ErrHandler отсутствуют CleanExit и Exit Sub. Что произойдет при успешном выполнении?

B: Процедура завершится, но не освободит переменные

explanation: Метка не прерывает поток выполнения. Без Exit Sub нормальный ход программы переходит к следующим строкам, то есть к коду обработки ошибки.
```

## 4. Пакетная обработка листов

Три копии кода для трех листов недопустимы: изменение правила пришлось бы вносить трижды. Одна рабочая процедура применяется к каждому объекту.

### Контракт ProcessOneSheet

- получает `Worksheet` параметром и не ищет лист по имени;
- не активирует и не выделяет лист: все обращения начинаются с `ws`;
- изменяет только выходные столбцы `I:K`, столбцы `A:H` остаются неизменными;
- завершается успешно или записывает ошибку в журнал;
- перед записью очищает выходную область (идемпотентность).

### Оркестратор

```excel
For Each ws In ThisWorkbook.Worksheets
    If Left$(ws.Name, Len(prefix)) = prefix Then
        ProcessOneSheet ws, revenueThreshold, costThreshold
        found = found + 1
    End If
Next ws
```

`ProcessReportSheets` выбирает объекты и не знает формулы отклонения, `ProcessOneSheet` рассчитывает один лист и не знает, как он выбран. Правило меняется в одном месте. `For Each` выбран, потому что индекс не нужен.

### Фильтр области

Коллекция `Worksheets` включает служебные листы «Сводка», «Параметры», «Журнал». Без фильтра расчетные столбцы появятся там, где их быть не должно. Признаком служит префикс имени, имя структурированной таблицы, служебная ячейка или список в конфигурации. Соглашение об именах записывается в инструкцию: лист «Январь отчет» не пройдет фильтр по префиксу «Отчет_» и будет молча пропущен. Поэтому после цикла полезно сравнить число найденных листов с ожидаемым.

### Сводка

Сначала обрабатываются единицы, затем агрегируются результаты. Контрольные значения при порогах 5 %:

| Лист | Строк | Критично | Отклонение | В норме |
|---|---|---|---|---|
| Отчет_Январь | 12 | 2 | 9 | 1 |
| Отчет_Февраль | 12 | 2 | 7 | 3 |
| Отчет_Март | 12 | 2 | 6 | 4 |

Итого 36 строк, план выручки 59 850 000 руб., факт 59 229 404 руб. Строки 5–7 листа «Сводка» рассчитаны на три листа; при большем числе листов запись дойдет до строки «Итого».

## 5. Пакетная обработка файлов и cleanup

Источники находятся в отдельных книгах, и появляется ресурс, которым нужно управлять: открытая внешняя книга.

### Жизненный цикл внешней книги

Переменная `wbSource` перед каждым открытием получает `Nothing`. После `Workbooks.Open` она содержит ссылку на книгу. Перед переходом к следующему файлу книга закрывается. Присваивание `Nothing` позволяет обработчику отличить «открытие не состоялось» от «книга открылась, ошибка возникла позже» и не закрывать несуществующий объект.

Режим `ReadOnly:=True` разграничивает ответственность: исходный файл – вход, процедура его не изменяет и закрывает с `SaveChanges:=False`.

### Перебор через Dir

```excel
fileName = Dir(folderPath & fileMask)

Do While fileName <> ""
    ' обработка одного файла
    fileName = Dir()
Loop
```

Первый вызов с маской возвращает имя первого файла, следующие вызовы без аргументов – имена остальных, пустая строка означает конец. Путь и маска читаются с листа «Параметры». Если папка недоступна, `Dir` может вернуть ошибку или пустую строку; первый вызов выполняется под ограниченным `On Error Resume Next`, результат проверяется явно, причина пишется в журнал.

### Проверка контракта до расчета

Наиболее опасна не остановка кода, а ситуация, когда столбец сместился, процедура прочитала соседние значения и выдала правдоподобные числа без ошибки. Структура и типы проверяются до расчета:

```excel
If Not HasRequiredHeaders(wsSource) Then
    Err.Raise vbObjectError + 1001, "ProcessFolder", "Неверная структура файла"
End If

CheckTypes wsSource, lastRow
```

`HasRequiredHeaders` сравнивает заголовки первой строки с ожидаемыми. `CheckTypes` проверяет, что значения в столбцах E:H – числа: `VarType(ячейка.Value2) <> vbDouble` означает текст, пустое значение или ошибку. Функция `IsNumeric` для этой цели не подходит: ее результат для текста вида «1 915 000» зависит от региональных настроек. Свойство `Value2` используется потому, что `Value` для ячеек с денежным форматом возвращает тип Currency.

`Err.Raise` переводит нарушение контракта в тот же механизм, что и ошибку выполнения: технические и структурные дефекты идут одним маршрутом в журнал.

### Закрытие при любом исходе

```excel
FileExit:
    If Not wbSource Is Nothing Then wbSource.Close SaveChanges:=False
    Set wbSource = Nothing
    On Error GoTo 0
    fileName = Dir()
    GoTo ContinueLoop

FileError:
    LogError fileName, "ProcessFolder", Err.Number, Err.Description
    Resume FileExit

ContinueLoop:
```

В листинге на листе «Код VBA» метки находятся в первой позиции строки. Закрытие размещено в блоке, к которому ведут и успешный путь, и обработчик. Если разместить `Close` только в конце основной ветви, при ошибке управление уйдет в обработчик в обход закрытия, и файл останется открытым. По смыслу блок соответствует `finally` в других языках. После `FileExit` обработчик отключается, чтобы следующая итерация не унаследовала состояние.

### Учебные файлы

- `01_January.xlsx`, `02_February.xlsx` – структура корректна, по 12 строк; совпадают с листами «Отчет_Январь» и «Отчет_Февраль», поэтому результаты можно сверить.
- `03_March_error.xlsx` – нет столбца «Факт затрат, руб.»: `HasRequiredHeaders` возвращает `False`, ошибка записывается в журнал, книга закрывается, обработка продолжается.
- `04_April_type.xlsx` – структура корректна, но в ячейке F10 значение «1 915 000» записано текстом: `CheckTypes` обнаруживает дефект до расчета.

## 6. Выбор между формулами, Power Query и VBA

Три вопроса определяют стартовый инструмент:

1. Нужен ли постоянно пересчитываемый результат в ячейке? – **формулы**.
2. Это преобразование табличных данных? – **Power Query**.
3. Нужно управлять последовательностью действий и объектами приложения? – **VBA**.

«Стартовый» означает, что сложная задача часто требует комбинации, но выбор начинается с механизма, который уже решает задачу.

```excel
Данные                    → Power Query
Расчет                    → формулы / DAX
Действия и оркестрация    → VBA
```

Формулы подходят для прозрачного пересчета по ячейкам. Power Query – для импорта, очистки, типизации и объединения таблиц; Folder connector получает список файлов и объединяет результаты. VBA – для действий над объектами: обновление запросов, проверка контрольных ячеек, формирование копий отчетов, управление файлами, журнал.

| Задача | Старт | Риск неверного выбора |
|---|---|---|
| Расчет показателя из ячеек | Формулы | Избыточный код |
| Импорт и очистка однотипных файлов | Power Query | Ручные циклы и хрупкие адреса |
| Управление книгами, листами, форматированием | VBA | Ручные действия в интерфейсе |
| Массовое объединение таблиц | Power Query | Переписывание готового механизма |
| Расчетная функция | Формула или UDF по сложности | UDF там, где достаточно LET |
| Исключительная ситуация, журнал, cleanup | VBA | Resume Next скрывает дефект |
| Полный регламентный процесс | Комбинация | Монолитный макрос |

### Сопровождаемость

Формула понятна большинству пользователей, шаги Power Query видны в редакторе запросов, код VBA скрыт и может менять состояние книги. Из равнозначных по результату вариантов выбирается тот, который проще проверять и поддерживать в конкретной команде. Техническая возможность не равна организационной целесообразности.

### Оркестрация

VBA может не выполнять трансформацию, а управлять готовыми компонентами: запустить `RefreshAll`, проверить контрольную ячейку, сохранить отчет в папку, записать журнал. Это устойчивее дублирования логики Power Query в коде. Монолитный макрос, самостоятельно читающий файлы, считающий модель, оформляющий отчет и управляющий выходом, трудно проверять и передавать.

```quiz
question: Ежемесячно приходят 25 однотипных файлов: их нужно объединить, привести названия и типы столбцов, рассчитать маржу и сохранить 12 копий отчета по филиалам. Какое распределение инструментов корректно?
A: VBA целиком
B: Power Query для импорта и типизации, формулы или мера для маржи, VBA для формирования и сохранения копий
C: Power Query целиком
D: Формулы целиком
correct: B
explanation: Задача состоит из трех слоев: загрузка и типизация, расчет, процедурные действия над книгами. Каждому слою соответствует свой инструмент.
```

## 7. Использование ИИ: проверка устойчивости процедуры

Языковая модель применяется для поиска необработанных путей выхода и незакрытых ресурсов. Поведение на конкретных файлах она подтвердить не может: оно проверяется запуском.

```excel
Ниже приведена моя процедура регулярной обработки на VBA и описание контракта источника:

[ВСТАВЬТЕ КОД ПРОЦЕДУР, ОПИСАНИЕ СТРУКТУРЫ ИСТОЧНИКА, ОЖИДАЕМОЕ ПОВЕДЕНИЕ ПРИ КОРРЕКТНОМ И ДЕФЕКТНОМ ФАЙЛЕ]

1. Найди пути выхода, на которых открытая внешняя книга остается незакрытой.
2. Проверь, есть ли перед обработчиком ошибок явный выход из нормальной ветви.
3. Найди широкие On Error Resume Next и предложи, как ограничить область действия.
4. Проверь, что структура и типы источника проверяются до расчета, а не после.
5. Укажи места, где пользовательская функция выполняет действия вместо вычисления.
6. Проверь, содержит ли журнал источник, этап, код и описание.
7. Оцени, какие части задачи логичнее отдать Power Query или формулам.
```

Предложения проверяются запуском на учебных файлах. Характерный признак ненадежного совета – оборачивание проблемного участка в `On Error Resume Next` вместо устранения причины.

## 8. Итоги занятия

1. Регулярный процесс повторяется без правки кода; успех выполнения и полнота результата различаются.
2. У процесса есть контракт входа; отказ от расчета при его нарушении корректен, если причина зафиксирована.
3. `Function` вычисляет, `Sub` действует; UDF не имеет побочных действий, все входы передаются аргументами.
4. Некорректный вход возвращается контролируемой ошибкой, а не пустой строкой.
5. Ошибка записывается в журнал с источником, этапом, кодом и описанием; перед обработчиком обязателен явный выход.
6. Широкий `On Error Resume Next` недопустим; область подавления – одна ожидаемая операция.
7. Пакетная обработка имеет фильтр области; оркестратор отделен от рабочей процедуры.
8. Структура и типы источника проверяются до расчета; внешняя книга закрывается при любом исходе.
9. Инструмент выбирается по природе задачи и сопровождаемости; регламентный процесс обычно комбинирует слои.
